# 祝福圖

> **這個資料夾裡的 `sample-*.jpg` 只是佔位圖。**
> 婚禮當天真正送給賓客的那批 Q 版照片屬於私人照片，不隨這個 repo 發佈。
> 自行部署時請把佔位圖換成你自己的圖片（做法見下面）。

## 怎麼放圖？

把所有要當「答對成語後的祝福圖」的照片，**直接丟在這個資料夾裡**就好。
副檔名支援 `.jpg / .jpeg / .png / .gif`。

**每張圖都要在 `preview/` 裡放一張同檔名的縮圖**（見下面「為什麼需要縮圖」）。

```
puzzles/
├─ README.md
├─ sample-1.jpg        ← 原圖（點開看的大圖）
├─ sample-2.jpg
├─ ...
└─ preview/
   ├─ sample-1.jpg     ← 縮圖，檔名必須跟原圖一模一樣
   ├─ sample-2.jpg
   └─ ...
```

啟動 Spring Boot 時 `PuzzleImageCatalog` 會自己把這裡所有圖片建成索引，
之後賓客只要猜對任何一個成語，就會從這個池子裡隨機抽一張回傳給他。

檔名沒有任何規則，掃描是看副檔名而不是前綴，所以直接用你自己的命名就好。

## 為什麼需要縮圖？

LINE 的圖片訊息有兩個網址欄位，大小上限**不一樣**：

| 欄位 | 用途 | 大小上限 |
|---|---|---|
| `originalContentUrl` | 點開後看的原圖 | 10 MB |
| `previewImageUrl` | 聊天室裡直接顯示的預覽 | **1 MB** |

兩個欄位如果都塞同一張大圖，只要那張圖超過 1MB，**聊天室裡就會顯示不出來**。
所以原圖放這個資料夾，縮圖放 `preview/`，程式會自動配對。

沒有對應縮圖的圖片，程式會退回「原圖同時當預覽」，並在啟動時印出 WARN，
例如：

```
WARN  這些祝福圖沒有對應的縮圖，會直接拿原圖當 previewImageUrl；... [sample-9.jpg]
```

看到這行就表示有圖漏放縮圖了。

## 建議尺寸

當初那批正式用圖是這樣壓出來的，可以照抄：

- **原圖**：長邊 1600px、JPEG 品質 88 → 約 250～500 KB
- **縮圖**：長邊 480px、JPEG 品質 82 → 約 35～60 KB

手機上看畫質完全夠，十幾張加起來也只有幾 MB，Docker build 和冷啟動都快很多。

## 注意事項

- 檔名建議用英文/數字（例：`sample-1.jpg`），中文檔名雖然程式有處理 URL 編碼，
  但用 ASCII 最不容易踩到坑。
- 圖片必須能透過你的公開 HTTPS 網址被存取到（`app.public-base-url`），
  例如 `https://abc123.ngrok.io/puzzles/sample-1.jpg`。
- 這個資料夾完全沒圖也不會壞，使用者答對時會 fallback 成純文字祝福。
